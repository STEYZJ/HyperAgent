## Step 1 - 定位 TUI 滚轮向下失效
- 上一步：TUI 已支持滚轮滚动、键盘翻页和历史命令。
- 这一步：复查 `hyperagent/runtime/tui.py` 的 curses 鼠标事件处理，并检查当前 Python curses 暴露的鼠标常量。
- 为什么这么干：用户反馈滚轮向下无效，需要先确认是滚动 offset 逻辑错误，还是 curses 没有上报对应事件常量。
- 执行内容：检查 `BUTTON4_PRESSED`、`BUTTON5_PRESSED`、`ALL_MOUSE_EVENTS` 和 `REPORT_MOUSE_POSITION`；当前环境中 `BUTTON4_PRESSED=65536`，`BUTTON5_PRESSED=None`。
- 效果：定位到向下滚轮失效的直接原因是 Python curses 未暴露 `BUTTON5_PRESSED`，代码 fallback 为 0 后无法识别 button5 事件。
- 下一步：为 ncurses button5 增加稳定 fallback 掩码，并补充滚轮方向单元测试。

## Step 2 - 修复 TUI 滚轮向下识别
- 上一步：已确认向下滚轮失效来自缺失 `BUTTON5_PRESSED` 常量。
- 这一步：改造 TUI 鼠标滚轮解析逻辑，使用 ncurses 五位 button event mask 作为 fallback。
- 为什么这么干：终端仍会报告 button5 wheel-down 事件，只是当前 Python curses 没有导出常量；按 ncurses 位布局解析能兼容这类环境。
- 执行内容：`curses.mousemask` 同时启用 `ALL_MOUSE_EVENTS` 和可用的 `REPORT_MOUSE_POSITION`；新增 `_mouse_scroll_delta` 与 `_mouse_button_event_mask`，button4 映射向上滚、button5 映射向下滚；新增测试覆盖 button5 pressed/clicked fallback。
- 效果：即使 `curses.BUTTON5_PRESSED` 不存在，`2 << 20` 和 `4 << 20` 这类 wheel-down 状态也能被解析为向下滚动。
- 下一步：运行 TUI 测试、编译检查和全量测试后提交并推送修复。

## Step 5 - 启动 `/thinking` 显示语义修正
- 上一步：TUI 已具备思考内容展开/折叠命令，但文案仍容易被理解成控制模型 API thinking 模式。
- 这一步：创建 `fix-thinking-display-semantics` 分支，准备把 `/thinking` 明确改成 reasoning_content 的显示展开开关。
- 为什么这么干：CLI 的 `--thinking enabled/disabled` 才是模型请求层开关；REPL/TUI 的 `/thinking` 应只影响是否展示模型返回的思考内容，避免用户误判运行状态。
- 执行内容：检查 `HyperAgentRepl`、`HyperAgentTui`、`AgentLoop` metadata 和现有测试，确认当前实现只影响显示层，但内部命名与提示文案需要修正。
- 效果：明确本阶段不改 provider 请求参数，只改显示状态命名、状态输出、TUI 状态栏、metadata 和测试。
- 下一步：重命名显示状态，更新 `/thinking status` 与思考内容显示文案。

## Step 6 - 修正 `/thinking` 显示层语义
- 上一步：已明确 `/thinking` 只应控制 reasoning_content 展开，不控制 API thinking 请求参数。
- 这一步：把 REPL/TUI 内部显示状态改为 `expand_reasoning_content`，并更新文案和 metadata。
- 为什么这么干：`show_thinking`、`thinking=on/off` 这类命名会让用户误以为命令会切换模型的 thinking 模式；使用 reasoning display 语义能把请求层和显示层分开。
- 执行内容：REPL `/thinking status` 输出 `model thinking` 与 `reasoning display`；展开文案改为 `【模型思考内容】`；折叠文案改为 `【模型思考内容已折叠，可用 /thinking on 展开】`；无 reasoning_content 时不显示折叠提示；TUI 状态栏和侧栏改为 `reasoning=expanded/collapsed`；AgentLoop metadata 保留 `thinking_displayed` 并新增 `reasoning_content_expanded`。
- 效果：用户可以清楚区分启动参数 `--thinking enabled/disabled` 和交互命令 `/thinking on/off/toggle/status` 的职责。
- 下一步：运行定向测试和全量验证，然后提交并推送修复分支。
