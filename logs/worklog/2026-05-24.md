## Step 1 - 对比 HyperAgent 与 Reasonix 的 Agent 调用逻辑
- 上一步：2026-05-23 已完成 HyperAgent 功能设计说明文档，并提交推送为 `cdc6beb docs: summarize HyperAgent feature design`；当前工作树仍保留 `.gitignore` 与 `logs/worklog/2026-05-22.md` 的既有未提交改动。
- 这一步：回答“HyperAgent 的 agent 调用逻辑和 Reasonix 是否不一样”，读取 HyperAgent 的 `agent_loop.py`、`action_loop.py`、`llm.py`、`action_repair.py`、`agent_tools.py`，并对照本地 Reasonix 参考实现 `src/loop.ts`。
- 为什么这么干：这个问题容易被“HyperAgent 已经做了 Reasonix 风格增强”误导；需要区分“借鉴了 Reasonix 机制”和“调用逻辑完全等同于 Reasonix”。
- 执行内容：确认 HyperAgent 普通对话走 `AgentLoop`，工具执行走 `AgentActionLoop`，LLM provider 是多供应商抽象；Reasonix 则以 DeepSeek-only `CacheFirstLoop` 为中心，把 `ImmutablePrefix`、`AppendOnlyLog`、`VolatileScratch`、tool repair、stats 和 context folding 深度绑定到同一主循环。
- 效果：结论是两者不一样。HyperAgent 当前更像科研工作流编排器 + Reasonix-inspired action loop；Reasonix 更像 DeepSeek-native cache-first coding agent loop。HyperAgent 已吸收 cache-first guidance、stable prefix hash、repair、usage/replay/stats，但没有完全采用 Reasonix 的全局 append-only prompt 和 DeepSeek 专用主循环。
- 下一步：如果要进一步接近 Reasonix，需要把普通 `AgentLoop` 与 `AgentActionLoop` 的上下文构造统一成明确的 `stable_prefix / semi_stable_context / volatile_suffix` 分区，并让 tool schema、session log、compaction、usage telemetry 在同一 loop invariant 下工作。
